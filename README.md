# Braketime

Braketime은 연속 운전 시간, 수면, 혈당 값을 차량 안에서 판단해 쉴 때를 음성으로 알려 주는 Pleos Connect(AAOS) 앱이다. 주행 중 터치는 0개이고 권고만 한다. 진단이나 치료가 아니고 운전을 막지 않는다.

> **혈당 값은 시뮬레이션이다.** CGM 실연동이 없다. 시연의 혈당과 수면은 모두 시나리오 입력이고 화면 표지에 그렇게 표시된다.
>
> 현대자동차그룹·42dot·Pleos의 공식 앱이 아니며 후원이나 승인을 받지 않았습니다.

시연 영상: 아직 없음. 사람이 정하거나 해야 할 일은 `docs/decisions.md` 맨 끝의 "제출 전 사람이 정할 것"에 있다.

## 3분 실행

서버, 폰, API 키, 네트워크 없이 차량 APK 하나로 돈다.

```bash
# 1. 에뮬레이터 부팅 (Pleos Connect AVD. 소리를 들으려면 -no-audio를 빼고 띄운다)
#    pleos는 Pleos Connect v2.1.0 이미지로 만든 AVD 이름이다. 자기 AVD 이름으로 바꾼다.
#    경로는 macOS 기본값이다. Windows·Linux는 Android SDK 폴더의 emulator/를 쓴다
~/Library/Android/sdk/emulator/emulator -avd pleos -no-snapshot -no-boot-anim

# 2. 차량 앱 설치 (-g는 권한을 미리 허용한다. 빼면 온보딩에서 묻고, 거부한 권한은 설정 > 지원 현황에서 다시 요청한다)
export PATH="$PATH:$HOME/Library/Android/sdk/platform-tools"   # adb를 찾지 못할 때
adb install -r -g apk/hyunkyo_Braketime_release.apk
```

저장소 폴더에서 실행한다. 설치 직후 `adb emu kill`로 에뮬레이터를 끄면 APK가 디스크에 다 쓰이지 않아 다음 부팅에서 앱이 사라질 수 있다(실제로 겪었다). 그때는 다시 설치한다. `adb reboot`로 재부팅했을 때는 앱이 남았다. 2026-11-13 전 debug 서명 APK가 깔린 기기에는 서명이 달라 `-r`로 덮어 설치되지 않는다. `adb uninstall com.conditiondrive.vehicle` 뒤 설치한다(앱 데이터가 지워져 온보딩부터 다시 한다).

3. 앱 목록에서 Braketime을 연다. 첫 실행이면 약 3초간 "주차 상태를 확인하고 있어요"가 뜬 뒤 온보딩이 나온다: 시작 > 허용 요청(또는 나중에) > 건너뛰기(말해 보기를 눌렀거나 마이크를 허용하지 않았으면 끝내기).
4. 아래쪽 **설정** 탭 > **시연 모드** > **혈당 안내 시나리오**를 누른다. 약 2분 40초 돌고, 표지가 "시연 끝"으로 바뀐 뒤 15초쯤 지나 실사용 화면으로 돌아온다. 시나리오와의 대조 결과는 화면이 아니라 `adb logcat -d -s CdDemoReport:I`로 본다.
5. 다른 시나리오는 같은 곳의 **기기 없는 피로 관리 시나리오**, **수면 부족 시나리오**다. 정차 화면(S2, S3)이 나올 때 같은 페이지의 **시연 끝내기**로 멈추거나 **처음부터 다시**로 재시작한다. 주행 화면(S1)은 터치를 받지 않으므로 그 페이지로 갈 수 없다.

표지에 보이는 뜻: 내장 시연은 시스템 Driving view가 실제 차량 상태(P, 0km/h)를 보여 주는 동안 앱만 시나리오의 주행 신호로 돈다. 그래서 표지에 "차량 신호는 시나리오 입력(시스템 화면은 실제 P)"이 붙는다. 표지 아래 자막에 앱 음성 문장과 시나리오 응답이 나오므로 소리를 꺼도 내용을 따라갈 수 있다. 실제 내비로 경로를 보내는 것은 **설정 > 시연 모드 > 이 장소를 실제 내비로 보내기**를 사람이 누를 때뿐이다. 이 버튼은 시연이 장소를 고른 뒤부터 나온다.

### 공기 모드(Vehicle SDK) 장면

깨끗한 에뮬레이터는 콘솔 재순환이 꺼져 있고(이미 바깥 공기) 콘솔 하트비트도 없다. 이 상태의 SC2는 V27을 묻지 않고, 자막에 "Vehicle SDK로 공기 모드 읽음: 이미 바깥 공기라 묻지 않아요"만 남긴다. 변경 장면을 보려면 시나리오를 누르기 전에 실행하고 하트비트를 끄지 않는다(`hb-stop` 전까지 또는 1시간 돈다).

```bash
tools/vc.sh hvac 'recirc=true'
```

변경 장면을 돌린 뒤에는 앱이 재순환으로 복원하므로, 다음 SC2는 V27을 묻고 하트비트가 없으면 아래 표의 셋째 줄로 간다. 하트비트를 다시 켜면 재순환 값이 true나 false로 바뀔 때가 있고, 조건은 일정하지 않다. 표의 첫째 줄을 다시 보려면 시나리오를 누르기 직전에 `tools/vc.sh hvac 'recirc=false'`를 실행한다. 하트비트가 꺼져 있으면 `tools/vc.sh state`의 `recirc_on`이 실제 차량 값과 다를 수 있으니(실측: 콘솔 false, 앱이 읽은 값 true), 상태를 보고 판단하지 말고 항상 이 명령을 넣는다.

| 시작 상태 | V27 | "응" 뒤 | 자막 |
| --- | --- | --- | --- |
| 재순환 꺼짐 | 묻지 않음 | | `Vehicle SDK로 공기 모드 읽음: 이미 바깥 공기라 묻지 않아요` |
| 재순환 켜짐, 하트비트 켜짐 | 물음 | 바깥 공기, 시뮬레이션 5분 뒤 복원(실측 약 2초 뒤) | `Vehicle SDK로 공기 모드 변경: 바깥 공기, 이후 재순환으로 복원` |
| 재순환 켜짐, 하트비트 꺼짐 | 물음 | 값이 그대로, "바깥 공기로 바꾸지 못했어요." | `Vehicle SDK로 공기 모드 변경 요청: 값이 그대로예요` |

### APK

| 파일 | 역할 |
| --- | --- |
| `apk/hyunkyo_Braketime_release.apk` | 차량 앱(제출용). 심사와 시연에 이것만 있으면 된다 |
| `apk/hyunkyo_BraketimeCompanion_release.apk` | 폰 동반 앱. 수면 값과 시뮬레이터 혈당을 서버로 보낸다. 서버 경로를 볼 때만 쓴다 |

파일명은 공모전 규칙 `팀명_앱이름_release.apk`를 따른다(팀 hyunkyo, 앱 Braketime). 패키지명은 개발 때 이름 그대로 `com.conditiondrive.vehicle`, `com.conditiondrive.companion`이다(`adb logcat`, `adb shell pm`에서 쓴다). 두 APK 모두 배포 키(인증서 CN=hyunkyo, APK Signature Scheme v2)로 서명돼 있다.

### 차량 신호로 돌리기 (영상용)

Driving view의 속도와 기어가 함께 움직이는 경로다. 설정 탭에서 **설정 제목을 5번** 누르면 숨은 설정이 열린다(페이지가 서버 주소로 바뀐다). 다시 **시연 모드**를 누르면 "실제 차량 신호 사용"이 보인다. 켜고 시나리오를 누르면 기어 줄마다 시계가 멈추고 표지에 "콘솔에서 D로 바꿔 주세요"가 뜬다. 시나리오가 끝나면 이 행은 다시 숨고 체크도 풀리므로 시나리오마다 다시 켠다.

```bash
adb forward tcp:8088 tcp:8088   # tools/vc.sh start가 함께 한다
tools/vc.sh start
tools/vc.sh scenario sc1        # 앱이 기다리는 기어를 그때마다 넣고, 끝나면 대조 결과를 출력한다
```

`scenario`는 앱이 로그(`CdDemoConsole`)로 알리는 기어 대기를 따라간다. 줄의 실제 시각은 음성과 인식 길이에 따라 달라 고정 시간표로는 맞출 수 없다. 시나리오를 누르기 전이나 뒤 어느 쪽에 실행해도 된다. 차량 신호 시연의 경유지는 실제 내비로 가서 지도가 앱을 덮으므로, 앱 슬롯을 눌러 돌아온다(앱이 이미 앞에 있을 때 누르면 지도로 넘어간다). 경로가 내비에 남으니 끝나면 안내를 종료한다.

| 콘솔 조작 | 명령 | 앱에서 일어나는 일 |
| --- | --- | --- |
| 출발 | `tools/vc.sh drive 80` | S1로 바뀌고 운전 시간을 잰다 |
| 정차 | `tools/vc.sh park` | 3초 뒤 S2 또는 S3, 휴식을 잰다 |
| 후진 | `tools/vc.sh gear R` | 음성을 멈추고 기어가 바뀌면 재개한다 |
| 공기 모드 | `tools/vc.sh hvac 'recirc=true'` | V27 "바깥 공기로 바꿔 드릴까요?" 전제 조건. 하트비트가 돌아야 변경까지 된다 |
| 주행 제한 | `tools/vc.sh gear D` | 플랫폼이 DO=true로 바뀌고 S1로 넘어가며 설정이 닫힌다. 이 이미지에는 제한만 강제하는 명령이 없다(`cmd hmg_car_service` 없음, `docs/research/platform-facts.md`) |

### 서버와 폰 경로 (선택)

없어도 위 시연은 전부 돈다. 볼 때만 띄운다.

```bash
tools/run-server.sh             # 127.0.0.1:8080
adb -s <폰 에뮬레이터> install -r apk/hyunkyo_BraketimeCompanion_release.apk
```

두 번째 에뮬레이터(폰 이미지)에서 확인한 경로다. 폰 앱 기본 주소가 `10.0.2.2:8080`이라 실제 폰은 `adb reverse`와 숨김 설정의 주소 변경이 필요하고, 이 경로는 시험하지 않았다. 차량 S5 > 연결된 기기 > 연결 코드 받기, 폰에서 코드 입력. 서버 경로는 실시간으로만 돈다(40분 회복은 압축 시나리오와 자동 테스트로 증명한다).

## Pleos 지침 대응

- CCP(로터리·다이얼)는 지원하지 않는다고 매니페스트에 선언했다(`com.hmg.rotary.ROTARY_SUPPORTED=false`). 모든 조작은 터치(한 번 누르기)이고 주행 화면에는 조작이 없다.
- 더 돌아갈 화면이 없을 때(오늘 탭, 주행 화면, 온보딩 첫 단계) Back은 앱을 끝내지 않고 뒤로 숨긴다(`moveTaskToBack`). 숨겨도 음성 안내는 계속된다. 기록·설정 탭은 오늘 탭으로, 설정의 열린 페이지는 목록으로, 온보딩은 이전 단계로 간다.
- 음성 안내마다 앞에 150ms 묵음을 둔다. Pleos 음성은 앱이 오디오를 만질 수 없어 재생 요청을 150ms 늦추고, 대체 Android 음성은 엔진 큐에 묵음을 넣는다(`docs/decisions.md` U-27).

## 테스트 환경

- Pleos Connect v2.1.0 에뮬레이터(Automotive, API 34, 2560x1440, density 160, user 빌드, 로케일 ko-KR)
- 폰 앱은 폰 이미지 에뮬레이터(API 36, 1080x2400)
- JDK 21, Gradle Wrapper, Android SDK. `compileSdk 36`, `targetSdk 34`(차량), `targetSdk 36`(폰), `minSdk 28`
- 실차와 실제 폰으로는 확인하지 않았다

## SDK·API·권한과 기능

| 사용처 | SDK·API | 권한 | 기능 | 시연에서 보이는 곳 |
| --- | --- | --- | --- | --- |
| 음성 안내 | TextToSpeech(ON_DEVICE) | `TTS_SERVICE` | F2~F7 | 내장 시연에서 실제 호출 |
| 음성 응답 | SpeechToText(ON_DEVICE) | `STT_SERVICE`, `RECORD_AUDIO` | F4, F3 | 실제 호출. 인식이 안 되면 시나리오 응답(표지에 표시) |
| 쉼터 위치 | FusedLocation → NaviHelper → LocationManager | `FUSED_LOCATION`, `ACCESS_FINE_LOCATION` | F3 | 실사용. 시연은 고정 좌표. 값을 주는 경로를 지원 현황에 표시한다. 에뮬레이터 기본 FusedLocation 값은 미국 좌표라 내비 위치로 넘어간다(`adb emu geo fix 127.0276 37.4979`를 주면 FusedLocation을 쓴다) |
| 경유지, 남은 시간 | NaviHelper | `NAVI_ROUTE`, `NAVI_ROUTE_SEARCH`, `NAVI_CUSTOM_MAP` | F2, F3 | 차량 신호 시연. 내장 시연은 사람이 누르는 버튼 |
| 공기 모드 | Vehicle HVAC | `CAR_CLIMATE`, `CONTROL_CAR_CLIMATE` | F10 | SC2 자막. 기본 상태는 읽기만 보이고, 변경은 위 "공기 모드 장면"의 조건에서만 보인다 |
| 주행 거리 | Vehicle Odometer | `CAR_DRIVE` | F1 재시작 복원 | 실사용 |
| 동승 인지 | Vehicle Seat | `CAR_SEATS` | F11 | 실사용. 값 방향 확인 전이라 항상 수치를 숨긴다 |
| 차속, 기어, 시동 | CarPropertyManager | `CAR_SPEED`, `CAR_POWERTRAIN` | F1 | 차량 신호 시연 |
| 주행 제한 | CarUxRestrictionsManager | | 화면 게이트 | 차량 신호 시연(D 기어) |

실출시에는 `CONTROL_CAR_CLIMATE`에 App Market 승인이 필요하다. 공모전 APK에서 쓸 수 있는지 명시한 공식 문장은 찾지 못했다. 주최 측에 따로 묻지 않고 알려진 한계로 둔다(결정 기록 J-08).

## 판단 규칙과 출처

| 규칙 | 값 | 근거 |
| --- | --- | --- |
| 주의, 정차 권고 | 연속 운전 1시간 45분, 2시간 | 2시간과 15분은 화물자동차 운수사업법 시행규칙 제21조·제22조 참고(사업용 화물차 규정, 일반 운전자 법적 의무 아님). 1시간 45분은 정차 권고 15분 전 예고 설계값 |

| 수면 앞당김 | 6시간 미만이면 30분 | 설계값 |
| 혈당 정차 권고, 회복, 대기 | 4.0, 5.0 mmol/L, 40분 | Diabetes Canada 2018 21장(캐나다 지침). 40분은 Grade C·Level 3, 1형 대상 |
| 혈당 주의 | 빠르게 내려가면 7.3 미만, 내려가면 5.7 미만, 변화가 작으면 5.0 미만 | 설계값 |

쉼터 목록은 한국도로공사, 공공데이터포털 표준데이터(졸음쉼터 2026-02-25, 휴게소 2026-09-17 기준)다. 데모용이고 운영 상태, 공사, 임시 폐쇄를 반영하지 않는다(`docs/poi-sources.md`).

## 모듈

| 모듈 | 내용 |
| --- | --- |
| `:core` | 판단 엔진, 음성 문구와 분류, 장소 선택, 시나리오, 공유 DTO. 안드로이드와 시연 심볼이 없다 |
| `:vehicle` | 차량 앱. 플랫폼 어댑터, 런타임, Compose 화면, 시연 |
| `:companion` | 폰 동반 앱 |
| `:server` | Ktor 서버. 판단하지 않는다 |

설계는 `docs/DESIGN.md`, 명세와 달리 정한 것은 `docs/decisions.md`, 테스트 표는 `docs/test-scenarios.md`, 시연 대조 리포트는 `docs/reports/`(차량 신호는 `real-signals.md`)에 있다.

**서버 없이 동작한다.** 안전 판단은 차량 앱의 `:core` 안에서만 돈다. 서버, 폰, 네트워크가 없어도 시간 규칙 전체가 돈다.

JVM 테스트 1685개(`:core` 699, `:vehicle` 626, `:companion` 184, `:server` 176. `:vehicle` 27개는 화면 갤러리 기록용, `:companion` 3개는 서버가 떠 있을 때만 돌아 평소에 건너뛴다). 에뮬레이터가 필요 없다. 시나리오 JSON을 JVM 테스트와 시연이 함께 쓰고, 표지와 금칙어, 주행 중 터치 0, 문서와 코드의 문구 일치를 시험이 지킨다.

## 개인정보와 안전 원칙

- 권고만 한다. 진단·치료 표현을 쓰지 않고 운전을 막지 않는다. 주행 중 터치를 요구하거나 받는 요소는 0개다.
- 건강 동의는 폰에서만 받는다. 측정값은 서버를 거치지만 서버에는 계정당 최신 1건만 항목별 유효 시각까지 있고 이력이 없다.
- 위치는 차 안에서만 쓰고 서버로 보내지 않는다. Pleos 음성은 ON_DEVICE 고정이다. Pleos 엔진이 실패하면 Android 기본 음성 엔진으로 넘어가는데, 이 경로의 인식은 오프라인 선호일 뿐 보장되지 않는다.
- 혈당 값을 받은 적 있는 사용자는 값이 끊기면 회복·출발 안내를 하지 않는다. 직전 값이 정차 권고나 주의 수준이었으면 주의를 유지하고 시간이 지나도 풀지 않는다. 유효한 값이 다시 오거나, 정차 중 S5에서 연결을 해제하거나 "끊김 보류 풀기"를 두 번 누를 때만 풀린다. 폰 쪽에서 연결을 해제해도 차의 보류는 풀리지 않는다(차가 401과 구별할 수 없다). 정차 권고(4.0 미만) 뒤의 보류는 마지막 값을 받은 때에서 40분이 지나야 풀 수 있다(`docs/decisions.md` D-31~D-33).
- 동승자가 있거나 모르면 음성과 화면에서 혈당 수치와 단어를 가린다. 정차 권고 음성만 안전 예외다.

## 알려진 한계

- **실차 미검증.** 시동 신호, 경유지 도착 이벤트, 좌석 값의 방향은 실차로 확인하지 못했다.
- **CGM 실연동 없음.** 혈당은 시뮬레이션이다. 제휴는 문의 계획이고 효과는 측정하지 않았다.
- **실제 소리와 마이크를 확인하지 않았다.** 음성 인식 성공률(H6 고정 문장 50개 × 3회), 음악 중 덕킹, TTS 첫 음절 잘림, 듣기 시작음과 마이크의 간섭을 측정하지 않았다. 2026-11-06에 바꾼 음성(V09·V10 "안전한 곳에", 고속 변형 V09H·V10H)도 귀로 듣지 않았다. 오디오 AVD에서 사람이 확인해야 한다(`docs/decisions.md` 제출 전 항목 12).
- **차량 신호 시연은 콘솔 스크립트로만 돌렸다.** `docs/reports/real-signals.md`가 README 절차대로 돈 release 결과이고, 사람이 콘솔을 누른 실행과 영상은 없다.
- 폰 앱의 카메라 QR 판독, 시스템 카메라 딥링크, Health Connect의 실제 수면·심박 값, 잠금 화면 알림, 6시간 동기화의 주기 실행은 확인하지 못했다(`docs/test-scenarios.md` 3장).
- **스크린샷과 리포트가 모두 지금 APK로 만든 것은 아니다.** 어떤 결과가 어느 APK에서 나왔고 옛 APK 결과에 그 뒤 변경이 왜 드러나지 않는지는 아래 "결과를 만든 APK"에 있다.
- **S4 기록 탭의 운전 시간은 앱이 기록한 사건 사이만 센다(U-25).** 앱이 4시간 이상 꺼진 채 달린 시간, 혈당 정차 권고가 이어지거나 도착이 가까워 재안내 기록 없이 4시간 이상 달린 시간은 S4 운전 시간에서 빠진다. 엔진이 재안내 때도 기록을 남기게 하는 것이 근본책이다(`docs/DESIGN.md` S4 "목록 행의 뜻").
- CCP 하드키 Back이 표준 Back 키로 오는지는 실차와 CCP로 확인하지 못했다. Robolectric 자동 시험과 Pleos 에뮬레이터의 `adb shell input keyevent KEYCODE_BACK`으로 봤다(`docs/test-scenarios.md` H18). 에뮬레이터에서는 첫 화면(오늘 탭, 주행 S1, 시연 중, 온보딩 1단계)의 Back이 태스크를 맨 아래로 옮기고 포커스를 왼쪽 Driving view로 넘겼다(Activity는 끝나지 않음). 숨김은 태스크를 뒤로 옮기는 것까지다. 그 뒤 그 영역에 무엇을 그릴지는 런처(시스템 창 관리)가 정하는 것으로 보인다(에뮬레이터 `dumpsys`로 본 추정). 에뮬레이터에서는 아래에 있던 내비가 다시 시작되지 않아 앱 화면이 계속 보였다(`dumpsys activity`에서 홈 영역은 `HomeActivity`가 topResumed, 이 앱 Activity는 RESUMED·`finishing=false`). 실차의 창 관리가 같은지는 모른다.
- 온보딩 3단계 "말해 보기"의 듣는 중·말하는 중 Back은 녹음과 음성을 멈춘다(2026-11-06 고침). 1c51 APK는 듣기 작업만 취소해 Pleos 음성 인식 녹음이 다음 인식 요청까지 97초 이어졌다. 지금은 취소가 엔진 `stop()`까지 이어지고, 정지 요청 뒤 취소가 겹쳐도 stop은 한 번만 간다(`ChainListener.listen`, `ChainSpeaker.sayOnce`). Pleos 에뮬레이터에서 Back 0.06초 뒤 stop이 불려 녹음이 끝났고, 1초 뒤 녹음 목록에 Pleos 음성 서비스의 음성 인식 세션이 없었다. 상태 표시줄 마이크 표시는 시스템 표시기대로 약 4초 뒤 꺼졌다(`docs/test-scenarios.md` H18). 실차 마이크로는 확인하지 못했다.
- 시스템 권한 대화상자에 플랫폼 문구 "알 수 없는 작업"으로 표시되는 항목이 있다. 앱이 바꿀 수 없다.
- **세로 창은 Pleos 폼 팩터 테스트(가상 디스플레이)로만 봤다.** 프리셋 6종 × 세로·가로에서 잘림·겹침은 없었고, 가로 S1 눈금 두 개("1:45", "2:00")가 붙어 보이는 것과 세로 한 창에서 S2 출처 줄이 빠진 기준을 가리키는 것은 고치지 않았다(`docs/test-scenarios.md` 5장). 실제 세로 화면 차량, 회전 중 상태 유지, 실차에서 처음 열릴 때의 기본 창 크기(Pleos 가이드는 방향 미지정이면 창 1개라고 하지만 에뮬레이터 주 디스플레이에서는 2창)는 확인하지 못했다. 처음의 `landscape` 고정은 세로 창을 레터박스해 뺐다(U-17). 폭 1100dp 미만 한 창에서는 연속 운전 막대와 "안내 시점" 행이 보이지 않는다(설계, DESIGN 8.1). 앞당김이 남았는데 수면 값이 없으면 왼쪽 사유 줄이 대신 알린다(U-29).
- 평문 HTTP(10.0.2.2, 127.0.0.1 한정)와 토큰·요약 평문 저장은 공모전 범위의 설계이고 **출시 불가**다. 출시 빌드에서는 평문 예외를 빼야 한다.
- APK는 2026-11-13에 만든 배포 키(인증서 CN=hyunkyo)로 서명돼 있다. 키 파일과 `keystore.properties`는 저장소에 넣지 않는다(`.gitignore`). 그 전 debug 서명 APK와 서명이 달라 덮어 설치되지 않는다(위 3분 실행).
- 혈당 기준은 캐나다 지침이고 40분은 Grade C·Level 3, 1형 대상이다. 국내 지침과 CGM 단독 판단 가능 여부는 확인하지 못했다.
- 저혈당 사고 약 4배는 심한 저혈당 **병력**과의 연관이다. 2천만 대는 2030년 목표이고 전 세계 누적 기준이다.
- 심박은 폰에서 표시만 하고 판단에 쓰지 않는다.
- **화물차휴게소 21곳은 앱이 고르지 않는다(P-15).** 원본 휴게소 종류가 `화물차휴게소`인 곳이다. 일반 차량이 쓸 수 없다는 근거는 찾지 못했지만 시설별로 확인하기 전까지 혈당 자동 경유지와 피로 제안에서 뺀다. 신탄진·매송처럼 일반 차량도 많이 쓰는 곳이 섞여 있어 정차 지점이 멀어질 수 있다. 되살리려면 허용 목록을 둔다(P-15 [뒤집기] ①). 종류 값은 2026-11-07에 내장 `poi.json`에 넣었고 855d부터 차량 APK에 들어 있다(지금 `apk/`의 7870은 855d와 서명만 다르다). 에뮬레이터에서 매송 화물차휴게소 두 곳의 2.5km 남쪽에서 시속 80으로 달리며 혈당 정차 권고를 내자 앱은 매송을 한 번도 요청하지 않고 일반휴게소인 화성휴게소부터 경로를 쟀다(2026-11-07). 시연(SC1~3) 고정 장소 칠곡휴게소(부산방향)도 이 21곳 중 하나다. 시연은 그 장소를 고정으로 넣어 그대로 안내한다.
- 이미 넣은 경유지는 지우지 않는다. 안내 중에 진입로를 놓치면 내비에 지나친 경유지가 남을 수 있다.
