# 내장 POI 출처

**데모용 데이터다. 실제 출시 전 갱신이 필요하다.** 한 시점의 공개 자료를 앱에 고정한 것이라, 신설·폐쇄·공사와 운영 시간을 반영하지 못한다. 현장 답사나 실주행으로 확인하지 않았다.

- 결과 파일: `vehicle/src/main/assets/poi.json` (468개, 약 118KB)
- 생성 스크립트: `tools/poi_build.py`, 시험 `tools/poi_build_test.py`
- 조사일: 2026-11-01

전국 범위 값은 포털 표준데이터 페이지에 함께 표시되는 표에서 읽었다. 공식 파일 내려받기는 쓰지 않았고 API 키도 쓰지 않았다. 표가 전체 행인지 포털의 총건수와 대조하지는 못했다. 경부선에서 졸음쉼터 31행, 휴게소 34행이 나오므로 시연 경로에는 충분하다.

## 좌표 확인

**좌표계.** 원본에 좌표계가 적혀 있지 않다. 십진 위도·경도이고, 아래 대조로 WGS84로 볼 수 있다고 판단했다. 구 측지계였다면 수백 미터 어긋난다.

| 장소 | 원본 | 대조 값(한국어 위키백과) | 차이 |
| --- | --- | --- | --- |
| 천안호두휴게소 | 36.730226, 127.263879 | 36.7302333, 127.2638528 | 약 3m |
| 망향휴게소 | 36.8556501, 127.180929 | 36.855374, 127.180880 | 약 31m |

표본 2건이다. 전체 좌표를 지도로 대조한 것이 아니다.

**스크립트의 자동 검사.** 좌표를 확인하지 못한 행은 넣지 않는다. 이번 생성에서 걸러진 행은 0건이다.

| 대상 | 제외 조건 |
| --- | --- |
| 공통 | 위도·경도가 숫자가 아니거나 비어 있음. 국내 범위 밖 |
| 졸음쉼터 | 좌표가 표의 시도 범위를 벗어남 |
| 휴게소 | 표에 시도가 없어서, 전화 지역번호의 시도 범위(0.35도 여유)를 벗어나면 제외 |

범위는 시도 경계의 대략값이라 같은 시도 안의 오류는 잡지 못한다.

## 알아 둘 한계

- **좌표로는 방향을 판별할 수 없다.** 같은 이름 쌍 17개 중 6개는 "진행 방향 오른쪽이 그 방향 시설"이라는 규칙과 어긋난다. `StopPicker`는 진행 방위 ±60°에 더해 `direction`의 도시 좌표(대략값)로 쌍 중 진행 방향 쪽을 고르고, 쌍이 없으면 명백히 반대(135° 이상)일 때 뺀다. 표기가 56종이고 시험이 빠짐없는지 본다. 그래도 고속도로가 굽으면 틀릴 수 있어 런타임의 경로 거리 검사(직선의 2배 초과 제외)가 한 번 더 걸러 낸다. 묻지 않고 넣는 혈당 자동 안내는 이 검사나 표기가 확인해 줄 때만 경유지를 넣는다. 측정에 실패하면 반대편을 안내할 수 있다.
- **휴게소 종류는 2026-11-07에 채웠다.** 처음 생성한 스크립트가 종류 열을 버려 2026-11-06까지는 215곳 모두 `null`이었다. 포털 휴게소 페이지의 표(기준일 2026-09-17, 215행)를 파일로 저장하지 않고 메모리에서 읽었다. `poi_build.py`를 모듈로 불러 행마다 id를 다시 계산했다. 215행 모두 내장 파일의 id와 맞았고 이름, 좌표, 방향도 같아 `facility`만 채웠다. 장소는 더하거나 빼거나 옮기지 않았다. 일반휴게소 187, 화물차휴게소 21, 간이휴게소 7이다. 일반 차량이 쓸 수 없다는 근거는 찾지 못했다. 시설별로 확인하지는 않았다.
- **화물차휴게소는 앱이 고르지 않는다(decisions.md P-15).** 시설별로 확인하기 전까지다. `facility`에 "화물"이 들어 있으면 `StopPicker.pick`이 뺀다. 묻지 않고 넣는 혈당 경유지와 피로 제안 둘 다 같다. 같은 이름 짝의 방향 판별에는 계속 쓴다. 종류를 모르면(`null`) 일반 휴게소로 본다.
- **21곳**: 경주(부산방향), 고성공룡나라(통영방향), 김천(부산방향·서울방향), 매송(목포방향·서울방향), 문경(양평방향·창원방향), 성주(양평방향·창원방향), 신탄진(서울방향), 영천(대구방향·포항방향), 옥산(부산방향), 옥천만남, 옥천(부산방향), 이서(순천방향·천안방향), 입장거봉포도(서울방향), 청주(서울방향), 칠곡(부산방향). 855d(2026-11-07)부터 차량 APK는 종류를 채운 뒤 빌드해 21곳이 빠진다. 855d는 직전 07dd와 `poi.json`만 다르고, 지금 `apk/`의 7870(2026-11-13)은 855d와 서명만 다르다.
- **신탄진·매송처럼 일반 차량이 많이 쓰는 곳도 빠진다.** "화물"이 들어 있는지만 보기 때문이다. 혈당 정차 경유지 후보에서도 빠져 정차 지점이 멀어질 수 있다. 위 목록을 사람이 보고, 일반 이용이 확인된 곳은 허용 목록으로 되살릴지 정한다(P-15 [뒤집기] ①). 혈당 경유지만 화물차휴게소를 허용하는 안도 P-15에 적었다. 시연 고정 장소 칠곡휴게소(부산방향)도 이 분류다. 시연은 그 장소를 고정으로 넣어 그대로 안내한다.
- **종류 열 이름은 `휴게소종류`다(2026-11-07 원본 표로 확인).** 스크립트는 이름이 바뀔 때를 대비해 `휴게소구분`, `휴게소유형`, `시설구분`도 순서대로 찾는다. 하나도 없으면 멈추므로 `REST_TYPE_FIELDS`에 더한다.
- **운영 시간, 공사, 임시 폐쇄를 반영하지 않는다.**
- 설계서 `PARKING`, `CONVENIENCE` 종류는 고속도로 밖 검색(카카오, 2차)용이라 이 파일에 없다.
- **카카오 검색 결과에는 종류가 없다.** `KakaoPlaceProvider`가 만드는 장소는 `facility`가 `null`이라 화물차휴게소 필터가 걸리지 않는다. 지금 차량 앱은 내장 목록(`BundledPlaceProvider`)만 써서 영향이 없다. 카카오를 연결할 때 이름이나 분류로 화물차휴게소를 표시할지 정한다.

## 갱신 방법

```bash
mkdir poi-pages
curl -o poi-pages/shelter.html https://www.data.go.kr/data/15028203/standard.do
curl -o poi-pages/rest.html https://www.data.go.kr/data/15025446/standard.do
python3 tools/poi_build.py --html-dir poi-pages --check   # 쓰지 않고 검증, 제외 목록, 종류별 개수, 화물차휴게소 목록만 출력
python3 tools/poi_build.py --html-dir poi-pages           # poi.json 갱신
python3 -I -B tools/poi_build_test.py                     # 스크립트 시험. :core:test의 PoiBuildScriptTest도 돌린다
./gradlew :core:test --tests '*PlaceCatalogTest' --tests '*ForbiddenWordsTest' --tests '*StopPickerTest'
```

`--html-dir` 없이 실행하면 스크립트가 직접 페이지를 읽는다. 이 맥의 python.org 빌드는 인증서 저장소가 없어 실패했고, 현재 `poi.json`은 curl로 받은 페이지로 만들었다. 2026-11-07의 종류 값은 curl 출력을 파일로 저장하지 않고 바로 읽어 채웠다. 인증서 검증을 끄지 않는다.

포털 표의 필드 이름이 바뀌면 스크립트가 멈춘다. 갱신 후 이 문서의 기준일과 행 수를 고친다. 다시 만들면 위 "알아 둘 한계"의 종류별 개수와 21곳 목록, `PlaceCatalogTest`의 id 목록도 고친다.
