# Braketime 디자인 토큰

이 앱은 Pleos Connect 시스템 UI 옆에 나란히 놓인다. 목표는 "시스템과 같은 집에 사는데, 공식 앱으로 오인되지 않는 화면"이다. 코드에서는 `CdTheme`(CompositionLocal)으로만 읽는다. hex를 직접 쓰지 않는다. Material3 컴포넌트는 쓰지 않는다.

## 1. 근거

### 1.1 실제 화면 관찰(`docs/research/pleos-home-day.png`)

시스템 UI에서 직접 샘플링한 값이다.

| 위치 | 값 |
| --- | --- |
| Driving view 배경 | #FFFFFF |
| 앱 영역(지도) 배경 | #F6F8FC |
| 상태바 배경 | #F7F7F7 |
| 음악 칩 면 | #F0F0F0 |
| 검색창 면, GNB | #000000 |
| GNB 선택 칩 면 | #575757 |
| GNB 선택 밑줄 | #FF9900 |
| 구분선 | #BDBDBD |

관찰한 규칙: 모서리가 전부 직각이다. 그림자·그라데이션이 없다. 검정 면과 얇은 회색 선이 구조를 만든다. 선택 표시는 주황 밑줄 하나뿐이다. 파랑은 현재 위치·방향에만 쓴다. 숫자는 가볍고 크고, 라벨은 작고 회색이다.

### 1.2 현대차 시각 언어를 옮긴 방식

공식 브랜드 가이드는 공개 문서로 확인하지 못했다. 그래서 **색과 로고가 아닌 구조**를 옮긴다.

| 출처 | 관찰 | 토큰으로 옮긴 결과 |
| --- | --- | --- |
| Seon 디자인 시스템(Red Dot 2023 보도) | 자연의 수평선 모티프, 단순하고 평평한 그래픽, 주행 중 정보 위계 | 구분은 1dp 수평선. 카드 없음. 시간 눈금도 수평선("Horizon") |
| hyundai.com/kr 계산값 실측 | 굵기 400~500 위주, 넓은 면, 절제된 색 | 큰 숫자를 굵게 쓰지 않음(W400). 넓은 여백, 화면당 정보 3개 이내 |
| Hyundai Sans UI 설명 | 가독성 중심, 굵기로 위계 | 굵기 2~3단계만 사용 |
| Sensuous Sportiness | 외장 철학. UX 규칙과 연결한 공개 자료 없음 | 공식 대응표가 아닌 해석: 비례, 긴장된 수평선, 군더더기 제거 |

**옮기지 않은 것**: Hyundai Blue #002C5F, Active Blue #00AAD2, Sand 색조, Hyundai Sans, 로고. 브랜드 색을 앱의 정체성으로 쓰면 공식 앱처럼 보이고, 실제 시스템 UI에는 이 색들이 쓰이지 않아 옆에 놓으면 튄다. hyundai.com의 6~10px 모서리도 옮기지 않았다. 웹사이트가 아니라 실제 차량 시스템 UI가 이웃이기 때문이다. 시스템 UI의 직각을 따른다.

글꼴은 Pretendard(SIL OFL 1.1, Reserved Font Name "Pretendard")다. 사용자 요청으로 Asta Sans에서 바꿨다(`decisions.md`). 한글 글자 높이, 숫자 높이, 줄 메트릭(hhea 합 1.193em)이 Asta Sans와 거의 같아(3.1) 시스템 UI 옆에서 크기와 줄 간격이 달라 보이지 않는다. 직선적인 고딕이라 직각·얇은 선 방향과도 맞는다. 가변 TTF `PretendardVariable.ttf`(Version 1.309, fontTools로 읽은 `fvar` wght 축 45~930, 기본 400)를 **수정·서브셋 없이** `res/font/pretendard.ttf`로 넣는다. Reserved Font Name 때문에 고친 파일은 이름을 바꿔야 해서다. OFL 원문은 `assets/licenses/Pretendard-OFL.txt`다. 굵기는 `FontVariation.weight`로 400, 500, 600 세 단계만 고른다.

색, 도형, 문구를 항상 함께 쓴다. NORMAL은 색을 쓰지 않는다. 색은 주의를 끌어야 할 때만 나타나고, 평소 화면은 시스템 UI처럼 무채색이다.

| NORMAL | 얇은 원(선 6dp) | 여유 | 글자·선 text1 #131417 | text1 #EDEEF2 |

| STOP | 채운 정팔각형(절단 0.29, 가운데 막대 없음) | 정차 권고 | 면 #B3261E(bg 대비 6.54), 글자 #FFFFFF(6.54) | 면 #FF4C28(bg 5.54, s1 5.01, **s2 4.25라 s2 위 금지**), 글자 #131417(5.54) |
| STOP 글자 전용 | | | #B3261E | #FF6A4D(6.51 / 5.89 / 5.00) |
| RECOVER | 원 + 두 막대(일시정지) | 쉬는 중 | 글자·선 #00704A(6.15 / 5.78 / 5.39) | #3DDC97(10.42 / 9.43 / 8.00) |

배지 문구 원문과의 차이: 명세의 "정상"을 "여유"로 바꿨다. 앱이 건강 상태를 판정하는 말로 들리지 않게 하기 위해서다. 내부 상태값은 `NORMAL`을 유지한다.

**색각 이상 대비**(Machado 2009, 심도 1.0, CIELAB 거리. 스크립트로 이 표의 값을 계산했다):

| 조합 | 적록 deutan (야간/주간) | 적색약 protan | 청황 tritan |
| --- | --- | --- | --- |
| 주의 / 정차 권고 | 25 / 51 | 45 / 69 | 62 / 58 |
| 여유 / 쉬는 중 | 27 / 36 | 35 / 42 | 50 / 46 |
| 정차 권고 / 쉬는 중 | 46 / 34 | 36 / 16 | 138 / 104 |
| 주의 / 쉬는 중 | 59 / 79 | 50 / 71 | 79 / 71 |

STOP 도형에 가로 막대를 넣지 않는다. 56dp에서 흰 막대가 든 빨간 팔각형은 도로의 진입 금지 표지로 읽혀, 권고만 하는 앱의 태도와 어긋난다. 채운 팔각형만으로 원(NORMAL), 삼각형(CAUTION), 원과 일시정지 막대(RECOVER)와 구분된다. 'P'형은 시스템 기어 표시 P R N D와 겹쳐 쓰지 않는다.

가장 약한 값은 야간 deutan의 주의/정차 권고(25)와 주간 protan의 정차 권고/쉬는 중(16)이다. 앞의 조합은 채운 면의 도형(삼각/팔각)과 문구로 벌린다. 뒤의 조합은 STOP과 RECOVER가 같은 때 나타나지 않고(주행과 정차로 화면이 다름), 도형도 다르다.

**금지**: 상태색으로 화면 전체 칠하기, 깜빡임, 주간 CAUTION 면을 윤곽 없이 쓰기, 파랑을 상태에 쓰기, 보라색(Pleos 자율주행 토큰), 비활성 회색 상태. 미지원 기능은 비활성 색이 아니라 문장으로 표시한다.

**주황 혼동 방지**: 탭 선택 #FF9900과 주의 #FFC224는 같은 화면에 있어도 의미가 겹치지 않게 한다. 밑줄은 2dp 선으로만, 주의는 면으로만 쓴다. S1에는 탭이 없으므로 주행 중에는 주황 밑줄이 없다.

**시연 표지**: faceStrong 면 + 반전 글자. 주의 색을 쓰지 않는다. 상태로 오인되면 안 된다. 자막은 onFaceCaption이다.

주·야 전환은 `isSystemInDarkTheme()`(AAOS uiMode)를 따른다.

## 3. 타이포그래피

### 3.1 물리 크기 계산

Pleos 기준: 핵심 정보 글자 높이 한국어 5mm(영문 문서는 4mm, **5mm 채택**), 일반 3mm. 최소 12sp는 3mm에 미달하므로 쓰지 않는다.

Pretendard 글리프 높이(em 대비, fontTools로 wght 400 인스턴스를 만들어 윤곽 경계 상자로 잼): 한글 '주' 0.813, '정' 0.868, 숫자 '1' 0.707, '0' 0.727, 영문 x 0.530. W500에서는 '주' 0.823, '정' 0.876이고 숫자는 같다. 가장 가는 W400의 값이 최악값이라 한글 0.813, 숫자 0.707로 계산한다. 한글 폭은 0.864em(W400, W500 같음), tnum 숫자 폭은 0.614em(W400)·0.628em(W500), 비례(pnum) 숫자 폭은 W400에서 '1' 0.438em부터 '4' 0.624em까지다. hhea 높이 합(ascent 1950 + descent 494, upm 2048)은 1.193em이다.

비교한 Asta Sans 값(같은 fontTools 방식, W500): '주' 0.809, '정' 0.869, '1' 0.707, '0' 0.727, 한글 폭 0.856em, tnum 0.609em, hhea 합 1.193em. 예전 문서의 Asta 값(80.9%)은 브라우저 캔버스로 W500에서 잰 것이라 굵기를 함께 적는다.

Pleos 레이아웃 SVG 좌표에서 뽑은 값(공식 수치표가 아님, 실측으로 확정):

| 화면 | 해상도 | mm/px | Portrait 창 | Landscape 창 |
| --- | --- | --- | --- | --- |
| 17 (Connect-S) | 2560×1440 | 0.1470 | 840×1184 | 1700×1184 |
| 14.6 | 2048×1152 | 0.1578 | 672×948 | 1360×948 |
| 12.9 | 1920×1080 | 0.1487 | 628×855 | 1274×855 |

에뮬레이터: 2560×1440, density 160, 1dp=1px. 실차 밀도 160은 가정이다. 에뮬레이터 값은 물리 크기 근거가 아니다.

필요 sp = 목표 mm ÷ 글리프 비율 ÷ mm/px. 17인치 기준 핵심 한글 41.8sp, 핵심 숫자 48.1sp, 일반 한글 25.1sp, 일반 숫자 28.9sp. 12.9인치도 41.4, 47.6, 24.8, 28.5로 같은 범위다.

### 3.2 스케일

| 토큰 | sp | 굵기 | 줄높이 | 17인치 한글/숫자 mm | 용도 |
| --- | --- | --- | --- | --- | --- |
| display | 160 | W400 | 1.1 | 19.1 / 16.6 | S1, S3 큰 숫자 |
| headlineM | 56 | W500 | 1.2 | 6.7 / 5.8 | 숫자 단위, 핵심 숫자, 핵심 문장, 쉼터 거리 |
| keyLabel | 48 | W600 | 1.2 | 5.7 / 4.99 | 상태 배지(한글 전용). **숫자 금지**. 17인치 숫자 기준 미달 |
| titleL | 40 | W500 | 1.3 | 4.8 / 4.2 | 정차 화면 제목 |
| titleM | 36 | W500 | 1.3 | 4.3 / 3.7 | 쉼터 이름, 값 |
| titleS | 32 | W400 | 1.4 | 3.8 / 3.3 | 라벨("다음 휴식까지") |
| bodyL | 30 | W400 | 1.5 | 3.6 / 3.12 | **숫자가 있는 문장의 하한** |
| bodyM | 28 | W400 | 1.5 | 3.35 / 2.9 | 한글 본문 |
| bodyS | 26 | W400 | 1.5 | 3.11 / 2.7 | 한글 출처 한 줄. 하한 |

- Pleos Label 24/20은 2.85mm, 2.38mm로 3mm에 미달해 쓰지 않는다.
- mm 열은 W400 최악값(한글 0.813, 숫자 0.707) × sp × 0.1470이다.
- display만 `fontFeatureSettings="pnum"`(비례 숫자)이고 나머지는 `"tnum"`이다. tnum이면 '1'도 0.614em을 차지해 160sp에서 '1' 한 자에 약 28dp가 비고 "12"가 "1 2"처럼 벌어진다. display는 왼쪽 정렬이고 뒤에 단위만 있어, 분이 바뀌어 폭이 달라져도 뒤의 단위가 몇 dp 옮겨질 뿐 시선을 끌지 않는다. 작은 크기의 숫자는 표나 목록 안에서 자리가 흔들리면 눈에 띄어 tnum을 유지한다. 모든 스타일에 `includeFontPadding=false`.
- 긴 문장을 스케일로 줄이지 않는다. 80자, 3줄을 넘으면 문구를 줄인다.
- 1차 범위는 런타임 크기 보정을 하지 않는다(`k=1`). ydpi를 믿을 수 없는 에뮬레이터에서 배치를 깨뜨릴 수 있어서다. S5 화면 정보에 `density`, `ydpi`를 표시해 실차 기록을 남긴다.

**폭 검증**(가장 좁은 12.9 Portrait, 내부 폭 548dp): "1시간 59분" = 숫자 3 × 0.624(pnum 최대폭 '4') × 160 + 단위 3 × 0.864 × 56 + 간격 2 × 16 = 299.5 + 145.2 + 32 = 477dp. 들어간다. 숫자가 모두 가장 넓은 자리라고 가정한 값이다.

### 3.3 줄바꿈

**한글은 어절 단위로만 줄을 바꾼다.** "알/려 드릴게요", "받/은 값도"처럼 어절 가운데서 끊기면 다시 이어 읽어야 해 정차 중에도 읽는 속도가 떨어진다.

- 구현: 모든 `TextStyle`에 `localeList = LocaleList("ko-KR")`를 둔다. 제목 계열(display, headlineM, keyLabel, titleL, titleM, titleS)은 `LineBreak.Heading`(줄 길이 균형 + 어절 단위), 본문 계열(bodyL, bodyM, bodyS)은 `LineBreak.Paragraph.copy(wordBreak = LineBreak.WordBreak.Phrase)`다. 기기 언어가 한국어가 아니어도 한국어 어절 규칙을 쓰게 로캘을 스타일에 고정한다.
- 확인: Pleos 에뮬레이터(API 34, 2560×1440, density 160) 실기 캡처에서 S3 "회복 기준 위로 오르면 / 40분 뒤 알려 드릴게요", S5 "연결을 해제하면 / 받은 값도 지워요", 표지 "(시스템 / 화면은 실제 P)"가 어절 경계에서 나뉜다. 글자 단위로 끊었다면 앞줄에 한 글자가 더 들어갈 자리가 있는 곳에서도 어절 전체가 다음 줄로 넘어가는 것을 봤다.
- 공백이 없는 긴 문자열(주소, 긴 영문)은 폭을 넘으면 강제로 끊겨 창 밖으로 넘치지 않는다(`LineBreakTest`).
- Robolectric은 플랫폼 줄바꿈 엔진의 어절 규칙을 반영하지 않아 갤러리 PNG에서는 글자 단위로 끊길 수 있다. 줄바꿈 판정은 실기 캡처로만 한다. 갤러리 PNG로 어절 줄바꿈 회귀를 판정하지 않고, 실기 캡처의 S5 기준과 출처, 시연 표지로 확인한다. 실기에서도 끊기면 표시 문자열의 한글 음절 쌍 사이에만 U+2060(WORD JOINER)을 넣고 의미 트리에는 원문을 두는 방법이 다음 단계다(실험에서 동작 확인, 지금은 쓰지 않는다).

## 6. 화면 구성

- Portrait에 핵심, Landscape 오른쪽에 추가 정보. 왼쪽 위치는 전환 후에도 변하지 않는다.
- 분기는 `BoxWithConstraints` 실제 폭으로 한다(≥1100dp이면 2창). 테스트 폭 628, 840, 1274, 1700dp.
- 화면당 정보 3개 이내, 1~2초 안에 이해.
- Driving view와 GNB는 플랫폼 소유라 가리지 않는다.
- 세로 방향은 위부터 상태 → 라벨 → 큰 표시 → 보조. 주행 중 시선이 같은 순서로 내려간다. S1의 "시뮬레이션 데이터" 같은 주석은 보조라 맨 뒤다. 정차 권고일 때만 라벨이 행동 지시라 text1이다.
- 오른쪽 창은 내용이 비어도 남긴다(주행 화면 왼쪽 위치 고정). 예외는 온보딩이다. 오른쪽에 둘 내용이 없어 창 하나(최대 840dp)만 그리고(`CdWindow(keepEmptyRight = false)`), 제목 줄 오른쪽에 단계 "1/3"(titleS text3)을 둔다.

## 7. 폰 동반 앱

### 7.3 한글 줄바꿈

**한글은 어절 단위로만 줄을 바꾼다.** "원/본은", "작/동해요"처럼 어절 가운데서 끊지 않는다.

- 구현: 모든 토큰의 `TextStyle`에 `localeList = LocaleList("ko-KR")`와 `lineBreak`를 넣는다. 제목류(display~titleM)는 `LineBreak.Heading`(Balanced, Loose, Phrase), 본문류(titleS~bodyS)는 `LineBreak.Paragraph.copy(wordBreak = LineBreak.WordBreak.Phrase)`. 기기 로케일이 en-US여도 한국어 규칙을 쓰게 로케일을 고정한다.
- 실기 확인(2026-11-03, AVD `daylist` API 36, en-US): C1~C4, 데이터 탭, 안내 막대, 가로, 다크, 글자 150%에서 어절 중간 끊김 0건. 그래서 폰은 U+2060(WORD JOINER)을 넣지 않는다. Robolectric은 Phrase를 반영하지 않으므로 이 규칙은 JVM 시험이 아니라 실기 화면으로 확인한다.
- 한계: Phrase는 API 33부터다. minSdk 28~32 기기에서는 예전처럼 글자 단위로 끊길 수 있다. 실기에서 끊김이 보이면 그때 3장에 적은 U+2060 방식(표시 문자열의 한글 음절 쌍 사이만, 의미 트리는 원문)을 폰에도 쓴다.
- 폭보다 긴 영문·URL(라이선스 원문의 주소 등)은 플랫폼이 글자 단위로 나눈다. 서버 주소와 코드 칸은 한 줄(`singleLine`)이다.
