# Braketime 결정 기록

역할별 검토(기획자, 심사위원, 사용자 조사, 백엔드, 프론트엔드)의 충돌과 명세 모순을 어떻게 풀었는지 적는다. 설계서는 `docs/DESIGN.md`다.

표시:
- **[명세와 다름]** 명세 문구나 값과 다르게 결정했다. 명세에 반영해야 한다.
- **[뒤집기 후보]** 사용자가 나중에 뒤집을 만한 결정이다. 되돌리는 비용을 함께 적었다.

해소 원칙:
1. 11장과 주행 중 터치 0개는 이유 불문 지킨다.
2. 안전 판단은 차량 안에서 돈다.
3. 플랫폼 실측(`platform-facts.md`)이 역할의 추정을 이긴다.
4. 명세 문구는 사실 오류, 11장 경계, 맥락 오류가 있을 때만 바꾼다.
5. 범위를 넓히는 제안은 `:core` 전이표를 건드리지 않고 실패해도 F1~F5에 영향이 없을 때만 받는다.
6. 사용자 조사의 인물은 인터뷰가 아닌 가설이다. 근거가 약하면 더 단순한 쪽을 택하고 현장 확인 항목으로 넘긴다.
